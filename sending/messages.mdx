One endpoint sends everything: [`POST /v1/messages`](/api-reference/messages/send-a-message). The `type` field decides the shape of the rest of the body. It defaults to `text`.

## The 24-hour window

This governs everything else on this page.

<CardGroup cols={2}>
  <Card title="Window open" icon="lock-open">
    The contact messaged you within the last 24 hours. Send anything — free-form text,
    media, interactive.
  </Card>
  <Card title="Window closed" icon="lock">
    Only an approved [template](/sending/templates) will go out. Free-form sends are
    refused.
  </Card>
</CardGroup>

LazyApp enforces this server-side. A free-form send outside the window fails with a clear error instead of quietly disappearing.

## Addressing a recipient

By phone number, in E.164:

```json
{ "to": "+919812345670" }
```

Or by business-scoped user id, when Meta gave you one instead of a number:

```json
{ "recipient": { "type": "bsuid", "value": "BSU-..." } }
```

## Types

<Tabs>
  <Tab title="Text">
    ```json
    {
      "type": "text",
      "to": "+919812345670",
      "body": "Your order is packed and leaves tonight."
    }
    ```
    Up to 4096 characters.
  </Tab>

  <Tab title="Template">
    ```json
    {
      "type": "template",
      "to": "+919812345670",
      "template": {
        "name": "order_shipped",
        "language": "en",
        "category": "utility",
        "components": [
          {
            "type": "body",
            "parameters": [
              { "type": "text", "text": "1042" },
              { "type": "text", "text": "Thursday" }
            ]
          }
        ]
      }
    }
    ```
    The only type that works outside the 24-hour window. `category` affects pricing, so
    set it accurately.
  </Tab>

  <Tab title="Media">
    ```json
    {
      "type": "image",
      "to": "+919812345670",
      "media_id": "1234567890",
      "caption": "Your receipt"
    }
    ```

    `type` is `image`, `document`, `audio`, `video` or `sticker`. Reference bytes three ways:

    | Field | Use when |
    | --- | --- |
    | `media_id` | You already [uploaded it](/sending/media) |
    | `media_url` | LazyApp should fetch a public URL and upload it for you |

    `filename` is worth setting for documents — it is what the recipient sees.

    For a **voice note**, send `type: audio` with `"voice": true` (and no caption — Meta rejects captions on audio).
  </Tab>

  <Tab title="Location">
    ```json
    {
      "type": "location",
      "to": "+919812345670",
      "latitude": 19.076,
      "longitude": 72.8777,
      "name": "Acme Retail, Bandra",
      "address": "Linking Road, Mumbai 400050"
    }
    ```
  </Tab>

  <Tab title="Contacts">
    ```json
    {
      "type": "contacts",
      "to": "+919812345670",
      "contacts": [
        {
          "name": { "formatted_name": "Asha Rao", "first_name": "Asha" },
          "phones": [{ "phone": "+919812345671", "type": "WORK" }]
        }
      ]
    }
    ```
    Between 1 and 5 contact cards.
  </Tab>

  <Tab title="Interactive">
    ```json
    {
      "type": "interactive",
      "to": "+919812345670",
      "interactive": {
        "type": "button",
        "body": { "text": "Reschedule your delivery?" },
        "action": {
          "buttons": [
            { "type": "reply", "reply": { "id": "tomorrow", "title": "Tomorrow" } },
            { "type": "reply", "reply": { "id": "weekend", "title": "This weekend" } }
          ]
        }
      }
    }
    ```

    Buttons, lists, call-to-action URLs, flows, address collection,
    `contact_information_request`, and [catalog / product](/sending/catalog) messages all live under
    `interactive`. The contact's choice arrives as a `message.received` [webhook](/webhooks/events).
    Cart checkouts arrive as `type: order` with `content.order`.
  </Tab>

  <Tab title="Reaction">
    ```json
    {
      "type": "reaction",
      "to": "+919812345670",
      "reaction": {
        "message_id": "wamid.HBgMOTE5ODEyMzQ1Njcw",
        "emoji": "👍"
      }
    }
    ```
    Send an empty `emoji` to remove a reaction.
  </Tab>
</Tabs>

## Replying to a specific message

Quote the message you are answering, so it threads in the recipient's client:

```json
{
  "type": "text",
  "to": "+919812345670",
  "body": "Yes, that size is in stock.",
  "context": { "message_id": "wamid.HBgMOTE5ODEyMzQ1Njcw" }
}
```

## Service window

Free-form messages only land within 24 hours of the contact's last inbound message. Outside that window, send a [template](/sending/templates).

`GET /v1/contacts/{contact}` includes `service_window` so you can choose the right message type before sending:

```json
{
  "uuid": "1a2b3c4d-...",
  "phone_number": "+919812345670",
  "service_window": {
    "open": true,
    "state": "expiring",
    "expires_at": "2026-08-20T14:30:00+05:30",
    "last_inbound_at": "2026-08-19T14:30:00+05:30"
  }
}
```

`state` is `open`, `expiring` (less than two hours left) or `closed`. If you send anyway and the window is closed, the refusal carries `code: customer_service_window_closed`. See [Errors](/concepts/errors).

## Scheduling

Add `send_at` and the response becomes `202` with a scheduled id instead of a sent message:

```json
{
  "type": "template",
  "to": "+919812345670",
  "template": { "name": "appointment_reminder", "language": "en" },
  "send_at": "2026-08-20T09:00:00+05:30",
  "ttl_seconds": 3600
}
```

`ttl_seconds` drops the message if it could not be sent within that window — better than a reminder arriving six hours late. List with [`GET /v1/messages/scheduled`](/api-reference/messages/list-scheduled-messages) and cancel with `DELETE`.

### How `send_at` is interpreted

There is no separate `timezone` field. The instant is taken from the string you send:

| You send | Interpreted as |
| --- | --- |
| `"2026-08-20T03:30:00Z"` | Absolute UTC |
| `"2026-08-20T09:00:00+05:30"` | Absolute instant with that offset |
| `"2026-08-20T09:00:00"` (no zone) | Wall clock in the API's timezone, which is **UTC** |

These three schedule the same instant (09:00 India Standard Time):

```json
{ "send_at": "2026-08-20T03:30:00Z" }
{ "send_at": "2026-08-20T09:00:00+05:30" }
{ "send_at": "2026-08-20T03:30:00" }
```

The classic bug is a naive local time with no offset — it is treated as UTC, so the message goes out hours early or late for Indian and other non-UTC businesses. Prefer an explicit offset or `Z`.

Responses return `send_at` as ISO 8601. Convert to the viewer's timezone at display time; do not assume it comes back in the offset you sent.

LazyApp does not offer profile "queues" that drip-feed posts into recurring slots. For a batch of reminders, compute each `send_at` yourself (or stagger in your worker) and create one scheduled message per send.

Statuses and webhooks for scheduled vs sent messages are covered in [Message lifecycle](/concepts/message-lifecycle).

## Confirming a send

Fetch any message by uuid with [`GET /v1/messages/{uuid}`](/api-reference/messages/retrieve-a-message). Prefer [webhooks](/webhooks/overview) in production; the GET is for confirmation and debugging.

## Metadata

Attach up to 20 string values. They come back on webhooks, which makes reconciliation easy without a lookup table:

```json
{ "metadata": { "order_id": "1042", "warehouse": "BOM-1" } }
```

## Direct send

Numbers enrolled in Meta's direct-send programme can send `utility` and `authentication` content without a pre-approved template, via [`POST /v1/messages/direct-send`](/api-reference/messages/send-without-an-approved-template). Marketing is not eligible. Check [capabilities](/concepts/capabilities) before relying on it.

## Ordering

Messages to the same recipient are sent in the order you call the API. Across different recipients there is no ordering guarantee, and none is needed.
